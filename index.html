01 · Why analyseCount steps, not seconds

Measure growth, not the clock

Problem
Seconds depend on hardware, language and compiler.
Idea
Count basic operations as a function of input size n.
Goal
How does the work grow when n grows? That is what Big O captures.

03 · Proving itLimit test + worked example

Limit test: L = lim f(n)/g(n)

LConclusion
L = 0f = o(g), so also O
0 < L < ∞f = Θ(g)
L = ∞f = ω(g), so also Ω
Worked example · f(n) = 3n² + 5n + 2
  • O(n²): for n ≥ 1, f ≤ 3n²+5n²+2n² = 10n²
  • Ω(n²): f ≥ 3n²
  • Both hold → Θ(n²)
  • It is also O(n³), but that is a loose bound
04 · CasesCommon misconception

Best, worst, average ≠ O, Ω, Θ

Best case
Θ(1)
Key at index 0
Worst case
Θ(n)
Key last or absent
Average case
Θ(n)
About n/2 comparisons
Linear search is O(n) and Ω(1) overall. Cases choose which input you analyse; the notations say how you bound the result. Any notation fits any case. Quick sort: best/avg Θ(n log n), worst Θ(n²).

06 · CountingRules + C++ examples

Seven rules to count steps

  • Drop constants: 5n → n
  • Keep the dominant term: n²+n+100 → n²
  • Sequential blocks add, nested loops multiply
  • Halving or doubling a variable → log n
  • Different inputs, different letters: O(a·b)
  • Recursion: write T(n), then solve it
examples.cpp
for (int i = 0; i < n; i++) sum += i;          // O(n)

for (int i = 0; i < n; i++)
  for (int j = 0; j < i; j++) cnt++;           // O(n²): 1+2+..+n

for (int i = 1; i < n; i *= 2) cnt++;          // O(log n)

for (int i = 0; i < n; i++)
  for (int j = 1; j < n; j *= 2) cnt++;        // O(n log n)

// T(n) = 2T(n/2) + n  →  O(n log n)  (Master Theorem)
